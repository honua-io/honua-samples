## Priority gaps

1. **P0 GA-001: Reconcile public GA vocabulary with release artifacts.** Buyers can read 'GA-tier core' while the site says source evaluation and no immutable server release exists; production commitments are therefore unauditable. Owner: `honua-io/honua-release`. [Existing issue](https://github.com/honua-io/honua-release/issues/59)
2. **P0 GA-002: Pin immutable server image, commit, and evidence lineage.** Customers cannot reproduce or roll back a candidate when tests are not tied to an image digest and commit. Owner: `honua-io/honua-release`. [Existing issue](https://github.com/honua-io/honua-release/issues/60)
3. **P0 GA-003: Add capability canaries, reset, rollback, and incident ownership.** Fixtures do not show that the deployed candidate serves the claim or can safely recover/reset. Owner: `honua-io/honua-demo-infra`. [Existing issue](https://github.com/honua-io/honua-release/issues/61)
4. **P0 GA-004: Admit fixture and live semantic receipts for every GA job.** Gallery/source success cannot establish the exact release job result across documented platforms. Owner: `honua-io/honua-samples`. [Existing issue](https://github.com/honua-io/honua-sdk-js/issues/543)
5. **P0 SEC-001: Close bounded COG hardening and object-locality proof.** Direct cloud raster serving is unsafe for GA while malicious TIFF, decompression-bound, and locality hardening remains open. Owner: `honua-io/honua-server`. [Existing issue](https://github.com/honua-io/honua-server/issues/3102)
6. **P0 PY-001: Repair governed Python staging auth and service binding.** The required Python live compatibility lane cannot prove its typed-field contract, while reseeding from contradictory infrastructure sources can silently expose the protected fixture or change consumer semantics. Owner: `honua-io/honua-demo-infra`. [Existing issue](https://github.com/honua-io/honua-demo-infra/issues/28)
6. **P1 SDK-001: Publish exact cross-SDK surfaces and version window.** JS is beta while Python/.NET are source previews; source coverage is not a supported multi-language rollout. Owner: `honua-io/honua-release`. [Existing issue](https://github.com/honua-io/honua-release/issues/31)
7. **P1 RAST-001: Publish raster/coverage limits, performance, and offload behavior.** Functionally correct coverage APIs remain operationally unsafe without budgets, streaming limits, and a durable-job boundary. Owner: `honua-io/honua-server`. [Existing issue](https://github.com/honua-io/honua-server/issues/3101)
8. **P1 PMT-001: Finish PMTiles managed lifecycle and live proxy proof.** Static reads work, but archive/publish lifecycle and cleanup are not a supported trunk SDK surface. Owner: `honua-io/honua-sdk-js`. [Existing issue](https://github.com/honua-io/honua-sdk-js/issues/1118)
9. **P1 FMT-001: Define GeoParquet/GeoArrow server-output semantic parity.** The JS runtime is strong, but canonical keying and cross-SDK output semantics do not support GA interoperability. Owner: `honua-io/honua-server`. [Existing issue](https://github.com/honua-io/honua-sdk-js/issues/1119)
10. **P1 JOB-001: Normalize OGC process lifecycle semantics across SDKs.** Users cannot rely on one job lifecycle when .NET lacks a bounded waiter, Python is source preview, CLI is absent, and server DELETE is best-effort cancellation. Owner: `honua-io/honua-samples`. [Existing issue](https://github.com/honua-io/honua-samples/pull/29)
11. **P2 MD-001: Keep Zarr, NetCDF, and HDF5 outside GA.** Premature GA would imply production slicing/security/performance not established by source implementation and partial metadata coverage. Owner: `honua-io/honua-server`. [Existing issue](https://github.com/honua-io/honua-server/issues/3103)
12. **P2 JOB-002: Keep cloud custom-code authoring and execution out of GA.** The AWS Batch server contract exists, but Studio author/publish UX, SDK wrappers, resources/retries/idempotency, bindings, log streaming, cleanup, and live proof do not. Owner: `honua-io/honua-samples`. [Existing issue](https://github.com/honua-io/honua-samples/issues/29)
